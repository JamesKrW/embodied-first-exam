# potted plant — i03 — PRIVILEGED MODE

You control a simulated adult human body in a furnished house (HumanCLAW: Habitat-Sim with Half-Physics, an HSSD
scene). The body moves only by **motion skills**: walk, turn, side step, step back, steps up or down, sit, and stop.
**Task (HumanCLAW's own words):** Find the potted plant and move until your body is touching the target, with zero distance to the target object.

## Scoring
HumanCLAW's NavSR@20cm: the episode ends with a **stop** while the body is within **0.2 m** of the bounding box of a potted plant (the nearest one; any potted plant in the scene counts). Ending without a stop (running out of the 100 actions) fails.

## Actions
An action is a row `[action_id, value]`:

| id | action | value |
|---|---|---|
| 0 | walk forward | stride in m: `0.2`, `0.4` or `0.6` (nothing else) |
| 1 | stop | `0`. Ends the episode: you declare you are done. Only a stop can succeed |
| 2 | turn in place | signed degrees, + left (counter-clockwise seen from above), - right; \|value\| clamped to [10, 120]; 0 is refused |
| 3 | climb up one step | `0` |
| 4 | sit down | target pelvis height in m, clamped to [0.15, 0.85] |
| 5 | step back | m, clamped to [0.10, 0.60] |
| 6 | side step | signed m, + left, - right; \|value\| clamped to [0.10, 0.50]; 0 is refused |
| 7 | walk down one step | `0` |

Each action except stop is one 0.5 s motion of the whole body (15 frames at 30 Hz), generated by HumanCLAW's
motion model and played out under physics: the body ends up close to, not exactly at, what was asked, and it can
bump into furniture (which can move). An episode allows **100 actions**, the stop included: the 100th action ends
it whatever it is.

## Deliverable
Leave three files under `/app/output/`. **Only the first is scored.**

| file | what goes in it |
|---|---|
| `trajectory.npz` | `actions`: a float array (T, 2), T <= 100, the episode's actions in order (`Env.save()` writes it). The verifier replays it from the frozen start twice, each time in a fresh process, and scores 1 iff both replays succeed under the rule above and end in the same state |
| `gen.py` | the script that produced it; it must run and reproduce `trajectory.npz`, reading nothing but `/app/instance.json` and files under `/app/output/` |
| `NOTES.md` | at most 20 lines: your final approach and why it works, and what you tried that failed |

Write `trajectory.npz` as soon as you have any trajectory, and overwrite it whenever you have a better one: the
time limit ends without warning.

## Tooling (already installed; `python` from any directory)
```python
from hc_tools import Env
env = Env()                          # the frozen episode, on the GPU (~30 s to build)
env.step(0, 0.4)                     # one action; returns env.state()
env.state()                          # position, heading_deg, pelvis_rise_m, actions_used/left, done, success,
                                     # body_target_distance_m, sits_so_far, pelvis_touches_target
env.targets()                        # the target objects' centres and bounding boxes, the rule
env.shortest_path([x, y, z])         # Habitat navmesh path from the body to a point
env.rgb()                            # the head camera's image
env.reset()                          # back to the frozen start (a fresh simulator), any number of times
env.save("/app/output/trajectory.npz")
```
`python /opt/tools/hc_tools.py replay /app/output/trajectory.npz` runs what the verifier runs (add `--video
out.mp4` to watch it). The motion model's noise is seeded at every reset, so the same actions from the start give
the same episode; check it with two replays. The source of every module is in `/opt/humanclaw/src/humanclaw_bench`
and `/opt/tools`.

## Resource limits
Limits for the whole trial, all its processes together (every simulator you start included): at most **16 GiB of GPU memory**, **24 GiB of memory**, **512 processes** and **20 GiB** of new files under `/app`, `/tmp` and `/root`. GPU memory counts what a process reserves (JAX, for example, reserves most of the card unless told not to). These limits may be enforced (from protocol v1.2 on): when enforcement is on, exceeding one for 60 s within any 2 minutes, or a process killed for lack of memory, ends the trial as a failure (reward 0), whatever the deliverable. A monitor outside your container measures every few seconds; the current values are in `/run/rcb-limits/usage.json`. When enforcement is on and GPU memory goes above 1.5 times its limit, the monitor also kills the process holding the most of it at once, to protect the machine; that alone does not fail the trial. CPU is capped at 8 cores for your container; the cap only slows you down.

## Time limit
You have 3600 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.

This is wall-clock time from the start of your session; the time a simulator takes to start counts. When it is up you are stopped without warning and only what is in `/app/output/` at that moment is graded, so save a deliverable as soon as you have one and overwrite it whenever you have a better one. Your session started when you received this task. `/run/rcb-limits/usage.json`, rewritten every few seconds, gives the time left on this limit (`time_left_s`) and its end (`deadline_utc`), counted from a little before your session started, so it never gives you more time than you have: read it (or run `date`) before you decide that time is short, never guess. Waiting counts too: a tool call that sends input to a process that keeps running (an interactive interpreter, a simulator loop, a server) can wait for the whole wait or yield time you give it (for example Codex's `yield_time_ms`) even when the answer is printed at once, so give such calls a short wait and poll again if the output is not complete, or run one-shot scripts that exit when they are done.
